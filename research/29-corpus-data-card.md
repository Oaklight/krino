# Canonical corpus data card — 2026-11-06

One page for the training arm. Definitions and per-file provenance are in
`research/25-corpus-inventory.md`; the licence audit is in
`research/30-canonical-source-licences.md`.

Three sources of numbers, kept separate so the card stays auditable:

- **Generated by `scripts/corpus_datacard.py`:** corpus sizes after dedup
  (`by_corpus`), tier, origin, type mix, choice-K, score levels, state length,
  and the three hard-label counters.
- **Generated by `scripts/corpus_licence_audit.py`:** records per licence group
  and the two exclusion scenarios.
- **Carried from `research/25`, `research/30`, or one-off counts:** the
  pre-dedup sum and its decompositions, the label-file row/id/duplicate figures,
  the coercion counts, the contamination scope and result, the licence verdicts
  and quotes, and the gap list.

The corpora are not in the repository, so a reader cannot regenerate the numbers
from the scripts alone. Run them against a data mirror; the generated sections
should match the JSON exactly.

The table shows items kept after dedup. Before dedup the components sum to
246,305: 2,274 synthetic items sampled into the 20K/30K keep their sampled copy,
and 665 typed-decisions items already in the 20K/30K are dropped from the full

RACE is the one source where the id is not the item. `race_short_passage_choice`
has 498 distinct questions over 144 passage ids (2 to 5 questions per passage).
All 498 are kept; the item key is (id, question), and the passage id is the
split group so questions on one passage stay in one split. RACE is the only
canonical file with this shape; every other file has unique ids.

Two synthetic numbers that must not be conflated:

- the `*_jev_labels.jsonl` sidecars hold **154,092 rows** over 152,966 distinct
  ids; 931 ids repeat across 1,126 duplicate rows (`education_assessment` 1,056,
  `game_strategy` 70);
- the assembled family + variant item set is **154,091 items**.

The two counts differ by one by coincidence, not by construction. Use 154,091 for
corpus size; use 154,092 only when counting label-file rows.

Dedup order is target 30K, residual 20K, typed-decisions, synthetic, then the
remaining corpora. Synthetic and typed-decisions therefore lose the ids they
share with the 20K/30K.

`gold` does not mean human-verified. It breaks down as:

- 154,091 model-authored synthetic labels (151,817 in the synthetic corpus plus
  2,274 sampled into the 20K/30K);
- 59,157 upstream dataset labels;
- 8,037 community-authored labels (`typed_decisions`, `openjev_authored144`).

`execution` is 16,081 apigen trajectory labels plus 6,000 constructed
abstention labels. No hard label is a Jev prediction; `teacher_probs` is always
an additional soft target.

**Hard-label usability:** 237,366 items are eligible for option/type CE
(CE/BCE/ordinal). 6,000 abstention items drive the abstain/answerable target
and must not drive option CE. Zero items fail eligibility after label
normalisation; 124/70 noul labels and 85/108 score labels in the two sampled
corpora are strings that require coercion.

### `answerable` is binary with an implicit default

The artifact has 6,000 explicit `false`, 237,366 unset, and zero explicit
`true`. Unset means answerable; only an explicit `false` marks abstention.
A filter written `answerable == True` returns nothing and still looks like a
successful filter.

Of the 6,000, 4,000 are noul rows that carry the implicit `false`/`true`
options and a valid `False` label. A hard-label trainer must mask them or it
learns "false" on removed support. The other 2,000 are choice rows whose kept
label is no longer in the options, including 224 Banking77 rows with the full
79-intent label space.

Training masks these rows in the loss; the residual trainer does not drop them
from the batch. Row-level id exclusion is for held-out leakage only. The
listwise trainer has no abstain head, so it skips an `answerable=false` row at
the top of its loss; that guard matters on the paired corpus, whose variants
keep a valid label. Training is per row, so masking and dropping give the same
task gradients; they differ on the abstain-head update and the display
denominator, which leaves task metrics comparable and abstain metrics not.
Census: `results/abstention/canonical_answerable_census.json`.

## Contamination and dedup

**Exact-match audit only; near-duplicate audit pending #235.** #235 reports 0
exact hits on the canonical set (243,012 at the time of the run; 243,366 after
the RACE correction). The near-duplicate MinHash check reports 5,734 clusters;
they are not yet adjudicated as contamination. This card is not a clean bill of
health.

The older 97,355-row figure from the first pass is a historical scope, not a
reproducible denominator: its parenthetical does not reconcile arithmetically
with the named files. Use #235's canonical-union result, not that number.

Item-level dedup is applied (id, except RACE at id + question). State-level and
near-duplicate dedup is #235's deliverable; until it lands, paraphrase and
near-duplicate pairs may cross the canonical set.

## Known gaps

The corpus covers classification/choice, boolean judgment (noul), and ordinal
scoring, plus tool selection, long-context choice, and constructed abstention.
It does not contain first-class training data for:

- ranking/reranking and retrieval pairs (no pairwise margin data);
- structured extraction and per-field verification;
- multi-question states sharing one state (batch equivalence);
- hierarchy / taxonomy selection;
- self-consistency and multi-sample agreement targets;
- continuous-score regression (scores are 3-6 levels);
- large-K selection above K=80.

The last gap bounds what any result from this corpus can claim. K is bimodal:
52,104 of 100,257 choice items sit at K=3-4, nothing sits between K=16 and K=79,
and the 2,979 tool-call items at K=79-80 are above every set the public
evaluation uses (the public tier maxes at 6) and above the 20-option training
cap. Those items are trained on a gold-anchored subset and are never measured
in-distribution. The head's capacity above K=80 is untested by construction.

Vision and image inputs are out of scope for the current arm. Date and count
arithmetic are handled in code, not in the corpus.

## Reproduction

```bash
python scripts/corpus_datacard.py \
  --root data/benchmarks --repo-root . --json /tmp/datacard.json

python scripts/corpus_licence_audit.py \
  --root data/benchmarks --repo-root . --json /tmp/licence-audit.json
```

If `typed_decisions.jsonl` sits outside `--root`, pass
`--typed-decisions <path>` to both scripts. They are single-process, stdlib-only
apart from `data.provenance` and `data.synthetic.family_to_typed_questions`, and
they exit if a primary file is missing, so a partial mirror cannot silently
produce a smaller card.
